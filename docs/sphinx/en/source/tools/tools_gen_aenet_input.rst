``abics_gen_aenet_input``
-------------------------------

When aenet is used as the trainer, the directory given by ``base_input_dir`` in the ``[train]`` section
must contain the three directories ``generate``, ``train`` and ``predict`` with the aenet input files
(see "Preparation of input files for aenet" in the :ref:`tutorial<sec_tutorial>` for their contents).
``abics_gen_aenet_input`` generates a template of these input files from the ``[config]`` and ``[train]``
sections of an abICS input file.
The generated settings are the ones of ``examples/active_learning_qe/aenet_train_input``;
use them as a starting point and tune them by hand as needed.

- Descriptor: Chebyshev basis (``radial_Rc = 8.0``, ``radial_N = 16``, ``angular_Rc = 6.5``, ``angular_N = 4``), ``RMIN 0.55``
- Network: two hidden layers of 15 nodes each (tanh activation); the potential files are named ``<element>.15t-15t.nn``
- Training: BFGS, 500 iterations, 10% of the data for testing

``abics_gen_aenet_input`` is used as follows::

    $ abics_gen_aenet_input -h
    usage: abics_gen_aenet_input [-h] [-o OUTPUT_DIR] [--force] [tomlfile]

    Generate default aenet training input files (generate/train/predict) from the
    [config] and [train] sections of an abICS input.toml file.

    positional arguments:
      tomlfile              abICS input file (default: input.toml)

    optional arguments:
      -h, --help            show this help message and exit
      -o OUTPUT_DIR, --output-dir OUTPUT_DIR
                            Output directory (default: train.base_input_dir from
                            the toml file, or ./aenet_train_input)
      --force               Overwrite existing non-empty output directories

- The elements covered are those appearing in the ``[config]`` section (all elements of
  ``base_structure`` and ``defect_structure``) minus the ``ignore_species`` of the ``[train]`` section.
- Unless ``-o`` is given, the files are written to ``base_input_dir`` of the ``[train]`` section
  (``./aenet_train_input`` if it is not set).
  If any of ``generate``, ``train`` or ``predict`` already exists there and is not empty, the tool stops
  with an error; ``--force`` overwrites them.
- If ``type`` of the ``[sampling.solver]`` section is ``aenetPyLammps``, ``predict/in.lammps`` for LAMMPS is
  generated instead of ``predict/predict.in`` (see :ref:`tutorial_aenet_lammps`).
  In this case every element seen by the sampling solver (the elements minus the ``ignore_species`` of
  ``[sampling.solver]``) must be among the trained elements, otherwise the tool stops with an error.
- A warning is printed if ``type`` of the ``[train]`` section is not ``aenet`` (only aenet inputs are generated).

The generated files are the following (for the MgAl2O4 spinel example, with oxygen excluded by ``ignore_species``)::

    aenet_train_input/
    ├── generate/
    │   ├── generate.in.head
    │   ├── Al.fingerprint.stp
    │   └── Mg.fingerprint.stp
    ├── train/
    │   └── train.in
    └── predict/
        └── predict.in        (in.lammps for aenetPyLammps)

For example, a template for the tutorial input file is generated by::

    $ cd examples/active_learning_qe
    $ abics_gen_aenet_input input-aenet.toml -o aenet_train_input_generated
    Generated default aenet training input files for species ['Al', 'Mg'] in aenet_train_input_generated
